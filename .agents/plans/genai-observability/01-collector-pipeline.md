# WP1 — Collector pipeline: image pin, managed config, GenAI processing

## Goal

`lotel start` runs a pinned collector image whose default config enables every GenAI-relevant collector capability that exists upstream. Existing lotel-generated configs are upgraded automatically.

Prerequisite state: clean `main`. No dependency on other work packages.

## Upstream facts

Verified 2026-11-14:

- **Image and processor:**
  - Docker Hub `otel/opentelemetry-collector-contrib:0.165.0` equals `latest` (pushed 2026-11-07). No `0.165.1` image tag exists.
  - The `gen_ai_normalizer` processor (contrib `processor/genainormalizerprocessor`) is alpha, traces only, and targets semconv 1.40.0. It was added in v0.152.0 as `genainormalizer`, renamed to `gen_ai_normalizer` in v0.153.0, and became alpha in v0.154.0.
  - README: https://github.com/open-telemetry/opentelemetry-collector-contrib/tree/main/processor/genainormalizerprocessor
- **Normalizer config:**
  - `sources` is a required, ordered list. Built-in names are `openinference` and `openllmetry`.
  - Per-source options: `remove_originals` (default false) and `overwrite` (default false).
  - Top-level option: `overwrite_schema_url` (default false).
  - The processor only modifies span attributes. It sets the scope `schema_url` to `https://opentelemetry.io/schemas/1.40.0` when it writes, unless one already exists.
- **Other components:**
  - `spanmetrics` connector: emits `traces.span.metrics.calls` and `traces.span.metrics.duration`, and accepts extra `dimensions`. It does not sum token attributes.
  - `redaction` processor: `allowed_keys`, `blocked_key_patterns`, `blocked_values`, `redact_all_types`, `summary`. It reads attribute values as strings unless `redact_all_types: true`. Key-pattern deletion works for any value type.
  - `transform` processor (OTTL): `delete_key`, `delete_matching_keys`, `truncate_all`, `ParseJSON`, `SHA256`.
- No GenAI-specific receiver, exporter, connector or OTTL function exists in contrib.

### Default config content (v2)

Keep the existing receivers, the batch processor and `health_check` unchanged. **Add `append: true` to each of the three `file/*` exporters**, so a collector restart does not truncate raw history. Add the following:

```yaml
processors:
  gen_ai_normalizer:
    sources:
      - name: openinference
      - name: openllmetry
connectors:
  spanmetrics:
    aggregation_temporality: AGGREGATION_TEMPORALITY_DELTA
    metrics_flush_interval: 5s
    metrics_expiration: 5m
    dimensions:
      - name: gen_ai.operation.name
      - name: gen_ai.provider.name
      - name: gen_ai.request.model
      - name: gen_ai.response.model
      - name: error.type
service:
  pipelines:
    traces:  { receivers: [otlp], processors: [gen_ai_normalizer, batch], exporters: [file/traces, spanmetrics] }
    metrics: { receivers: [otlp, spanmetrics], processors: [batch], exporters: [file/metrics] }
    logs:    unchanged
```

Rules:

- **Use delta temporality.** With the default cumulative temporality, the connector re-emits every live series on every flush, even when idle. `metrics.jsonl` would then grow forever, and ingest could never reach `records: 0`.
- Verify the keys `aggregation_temporality`, `metrics_flush_interval` and `metrics_expiration` against the spanmetrics README at the pinned version during G1.
- `append: true` is required. WP1 restarts the collector automatically, and schema-v2 rebuilds (D4) read raw JSONL. Without `append`, every restart deletes the history that the rebuild depends on. During G1, confirm in the 0.165.0 fileexporter README that `append: true` is valid without rotation settings.
- Place `gen_ai_normalizer` before `batch`.
- Do not set `remove_originals`. Keeping the originals keeps OpenInference and OpenLLMetry debugging possible.
- Do not set `overwrite`. Native OTel attributes win.

### Managed-config refresh (`ResolvePaths`)

Decision table for `~/.lotel/collector-config.yaml`. This table does not apply to the CWD `lotel-collector.yaml`, which is never touched.

| File state | Action |
|---|---|
| Absent | Write `DefaultConfig` |
| First line matches `^# lotel-managed-config v(\d+)( |$)` and N < 2 | Overwrite with `DefaultConfig` |
| Same pattern and N == 2 | No-op |
| Same pattern and N > 2 | No-op. Print to stderr: `lotel: collector config v<N> is newer than this lotel (v2)` |
| No managed header (any content) | Copy the file to `collector-config.yaml.bak.<unix-seconds>`. Overwrite it with `DefaultConfig`. Print one line to **stderr**: `lotel: replaced ~/.lotel/collector-config.yaml (backup: <path>); put custom config in ./lotel-collector.yaml (see README#genai)` |

Rationale: the confirmed application context requires no compatibility. The real legacy file on the developer machine has no header. It is a pre-Docker file whose exporters point at host paths (`~/.lotel/data/...`), which are wrong inside the container, so it is not byte-equal to any known default. A "keep if edited" rule would silently leave GenAI processing off. The CWD `./lotel-collector.yaml` remains the supported place for custom config.

Write with the existing pattern: write to `path+".tmp"`, then rename. Return an error only for I/O failures.

### Stale running collector

Today `Start` returns early when the container is running (`collector.go:131-134`). That leaves an old `latest` collector with the old config in place, and `health` still passes.

New behavior:

1. Compute `cfgHash` as the lowercase hex SHA-256 of the resolved config file bytes. Store it in `State.ConfigSHA256` on start. `State.ConfigPath` already stores the absolute config path.
2. If the container is running, call `restartDecision(readState(), defaultImage, absCfgPath, cfgHash)`:

| Condition | restart | warning |
|---|---|---|
| state is nil (container running, no state file) | true | — |
| `state.Image != image` | true | — |
| `state.ConfigPath != cfgPath`, meaning a different directory or a different config file | **false** | `collector is running with config <state.ConfigPath>; this directory resolves <cfgPath>. Run 'lotel stop' first to switch.` |
| same path, `state.ConfigSHA256 != cfgHash` | true | — |
| otherwise | false | — |

3. When `restart` is false, print the warning (if any) to stderr, then today's "already running" message, and return nil.
4. When `restart` is true, print `Collector config or image changed; restarting.` to stdout. Call `Stop`, then continue with the normal start path. Raw JSONL survives because of `append: true`.

### Redaction recipes

These are complete collector configs that users copy to `./lotel-collector.yaml`. Each one is the v2 default plus one `transform` processor.

- Traces pipeline order: `[gen_ai_normalizer, transform/genai_content, batch]`. The recipe processor must run **after** the normalizer. Otherwise the normalizer rebuilds `gen_ai.*.messages` from unredacted OpenInference originals.
- Logs pipeline order: `[transform/genai_content, batch]`.

Content key set (regex, used by both recipes):

- `^gen_ai\.(input|output)\.messages$`, `^gen_ai\.system_instructions$`, `^gen_ai\.tool\.(definitions|call\.arguments|call\.result)$`
- legacy `^gen_ai\.(prompt|completion)(\..*)?$`
- OpenInference `^(input|output)\.value$` and `^llm\.(input|output)_messages\..*$`
- OpenLLMetry `^(gen_ai|llm)\.(prompts|completions)\..*$`

Recipes:

- `genai-redact-content.yaml` **deletes** the matching keys with OTTL `delete_matching_keys`. It applies to span attributes, span event attributes and log record attributes. For log records whose `event_name` starts with `gen_ai.` and whose body is a map, it also deletes the matching keys from `body`. Deletion through OTTL is chosen over the `redaction` processor, because the redaction processor masks values instead of removing keys.
- `genai-hash-content.yaml` replaces each matching key's value with `SHA256` of its string form. The contexts are the same as the redaction recipe.

The OTTL statement syntax is verified only by the behavioral test below, not by this plan.

## Tests and acceptance

Any collector start whose config lacks `append: true` truncates history. That includes the first restart, a stale binary, or a CWD `lotel-collector.yaml` without `append`. ## Risks and edge cases

- The `validate` subcommand of the contrib image may require `--config=` (with an equals sign). Use that form.
- `spanmetrics` emits metrics for *all* spans, not only GenAI spans. The resulting volume is acceptable locally. Document it in [05](05-documentation.md).
- After upgrading lotel, a manual `lotel stop` is no longer needed. The next `lotel start` detects the image or config change and restarts. An edit to the *same* resolved config file also triggers a restart, through the hash comparison. A different resolved path only warns.

## Exclusions

- No new CLI flag for redaction. Users opt in through the CWD config.
- No change to ports or the health endpoint.
